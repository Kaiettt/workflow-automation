## Problem Statement

Now that the backend can handle the Google OAuth flow, the frontend designer UI needs to provide the user with a way to trigger this flow, wait for it to complete, and then immediately use the new credential.

## Solution

Implement a "Connect Google" button in the node configuration sidebar. This button will open a popup window to the backend auth endpoint. The frontend will listen for the `oauth-success` message from the popup (which now contains the tokens), and store them directly in the workflow definition payload to be sent during save/publish APIs.

**NOTE (Architectural Change)**: We no longer fetch connectors or credentials from the API to populate a dropdown. We just provide a "Connect" button that captures the OAuth tokens and embeds them into the node's config so the backend can create the credential records during the workflow save/publish steps.

## User Stories

1. As a user, I want to click an "Add Connection" button in the node settings so that I can link my Google account to FlowPilot.
2. As a user, I want the designer to automatically detect when I have successfully authenticated in the popup so I can immediately select my new credential and continue building my workflow.

## Implementation Decisions

- **UI Update**: 
  - In `DesignerPage.tsx` (or the node properties sidebar), when configuring a Google node (Google Sheet or Gmail), show a dropdown for `credential_id`.
  - Next to or below the dropdown, add an "Add Connection" button.
- **Popup Flow**:
  - The "Add Connection" button calls `window.open('/api/integrations/google/auth', 'OAuth', 'width=500,height=600')`.
- **Event Listener**:
  - Set up a `message` event listener in the React component (e.g. inside `useEffect`).
  - When the event data matches `oauth-success`, it means the backend callback has finished successfully.
- **Data Refresh**:
  - Upon receiving the signal, call the API to fetch the updated list of credentials for this user.
  - Automatically select the newly created credential in the dropdown.

## Testing Decisions

- Test the `window.open` and `postMessage` flow using Cypress/Playwright or by mocking the `window` object in unit tests to ensure the component re-fetches credentials when a success message is received.

## Out of Scope

- Managing multiple Google accounts for the same user in complex ways (for the MVP, we just fetch the list and pick the newest one).
