## Problem Statement

Filter works on in-memory arrays. Completing manual → sheet → filter → Gmail requires reading rows from Google Sheets and sending mail, using secrets stored in `connector_credentials`.

## Solution

Replace stub bodies for `GoogleSheetReadRowsExecutor` and `GmailSendExecutor` (`INodeExecutor` implementations from `contracts.md`). Before those executors run, the engine resolves `credential_id` from config against `connector_credentials` (UUID), decrypts with `EncryptionUtil`, and passes plaintext only as `execute({ credential })`.

Read `contracts.md` and the encrypted-row examples in `data-now.md` (do not commit live secrets; tests mock Prisma + `googleapis`).

## User Stories

1. As a user, the sheet node returns an array of objects from `spreadsheet_id` / `sheet_name`.
2. As a user, Gmail sends one message per input item to that item’s `email`, with `{{variable}}` interpolation on `subject` and `body`.

## Implementation Decisions

- **Vault**: Engine (not the Google client) loads the credential, checks owner + Google connector, decrypts. Executor receives usable Google tokens via `credential`; it must not query `connector_credentials` itself.
- **Sheets** (`GoogleSheetReadRowsExecutor`): `googleapis` read; first row as headers; remaining rows as objects. Output schema is the row array; input schema is null.
- **Gmail** (`GmailSendExecutor`): parse input as `[{ name, email }, ...]`; loop items; send to `email`; interpolate `subject` / `body` templates. Output schema is null; write `{ sent_count, success_count, failed_count }` into the node log `output` field for operators.
- **Errors**: Google/API failures → that node `FAILED`, execution `FAILED`, no further nodes. Sanitize errors (no tokens).
- **Placeholder `google-credential`**: treat as invalid id (400/failed node), not as a special lookup. Designer must persist the UUID for a real run.

## Testing Decisions

- Unit: mock Sheets/Gmail clients; interpolation; filter example from `spec.md` yields two sends.
- Unit: decrypted secret does not appear in logged input/output or thrown messages.

## Out of Scope

- OAuth connect UI (already in phase 3).
- Token refresh.
- Writing credential UUIDs into the designer (call out if Run fails on the current fixture).
