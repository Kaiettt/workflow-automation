## Problem Statement

Publish exists, but there is no screen to pick a published version and start a manual run. The MVP trigger is `POST /api/executions`; a user needs list + detail + Run.

## Solution

Add version read APIs and two pages in `frontend/src/features/workflow` (feature folders, React Query for server state, service layer for HTTP — not in components). Wire `react-router-dom` (already a dependency). Run on the version detail page calls 4.1’s endpoint and shows the returned execution status and node logs.

Depends on **4.1** for `POST /api/executions`. GET endpoints live in the designer module (repository `findByWorkflowId` / `findById` already exist).

## User Stories

1. As a user, I open a list of published versions for a workflow.
2. As a user, I open one version and see its identity and graph summary.
3. As a user, I click **Run** and the app starts that version via the executions API and shows the result.

## Implementation Decisions

### Backend

- `GET /api/workflows/:id/versions` — versions for that workflow the caller owns, newest `version_number` first. DTO: `id`, `versionNumber`, `publishedAt` (no full definition).
- `GET /api/workflows/:id/versions/:versionId` — one version: same metadata plus `definition`. 404 if id mismatch or not owned.
- Follow existing `{ success, data }` envelope. JWT guard.

### Frontend

- Routes: `/workflows/:workflowId/versions` (list), `/workflows/:workflowId/versions/:versionId` (detail + Run). Keep designer reachable (e.g. `/workflows/:workflowId` or existing create flow).
- Add `@tanstack/react-query` as a **direct** dependency and a `QueryClientProvider` (devtools already present).
- List page: query the list endpoint; each row links to detail (`versionNumber`, `publishedAt`).
- Detail page: query the version; show version number, published time, node names/`data.key` from `definition.nodes`. **Run** button mutation → `POST /api/executions` with that `versionId`. Disable while pending; after success show execution `status` and per-node log status (and error message if failed).
- Components do not call axios; `workflow.api.ts` / `workflow.service.ts` (or an `execution` service) + React Query hooks.
- Tailwind + existing shadcn `Button`. No new designer canvas required (read-only summary is enough).

### Entry

From the designer, add a control to open the versions list for the current `workflowId` after publish.

## Testing Decisions

- Backend integration: list/detail 200 for owner; 404 for unknown version; definition on detail matches the published snapshot.
- Frontend: hook/service tests or component tests with mocked API — list renders versions; Run posts the detail page’s version id.

## Out of Scope

- Editing a published version (immutable).
- Execution history index (detail may show only the latest Run response).
- Fixing OAuth `credential_id` placeholder in the designer (still required for a live Google run).
