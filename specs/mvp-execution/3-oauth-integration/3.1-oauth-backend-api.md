## Problem Statement

To connect Google accounts, the backend needs to handle the OAuth 2.0 authorization code flow. It must provide an endpoint to start the flow (redirecting to Google) and a callback endpoint to receive the code, exchange it for tokens, encrypt those tokens, and store them securely in the database.

## Solution

Build the backend API routes and the necessary encryption utility to handle the Google OAuth flow.

**NOTE (Architectural Change)**: As discussed, the backend callback endpoint will NO LONGER save the credential record directly to the database. Instead, it will pass the tokens back to the frontend. The frontend will include these credentials in the workflow definition, and the backend will create the `connector_credentials` records during the **Workflow Draft Save** and **Workflow Publish** APIs.

## User Stories

1. As a backend system, I want an encryption utility so I can securely store sensitive OAuth tokens using AES-256-GCM without logging them in plaintext.
2. As a user, when I hit the auth endpoint, I want to be redirected to the Google consent screen.
3. As a user, after I approve access, I want my token to be saved to my account so the execution engine can use it later.

## Implementation Decisions

- **Encryption Utility**: 
  - Create an `encryption.service.ts` or utility that uses Node's native `crypto` module.
  - Implement AES-256-GCM encryption and decryption.
  - Require an `ENCRYPTION_KEY` environment variable.
- **Backend Auth Endpoint (`GET /api/integrations/google/auth`)**:
  - Initializes the OAuth2 client using the `googleapis` package.
  - Generates the auth URL requesting `spreadsheets.readonly`, `gmail.send`, and `offline` access.
  - Redirects the incoming request to this generated URL.
- **Backend Callback Endpoint (`GET /api/integrations/google/callback`)**:
  - Receives the `code` query parameter from Google.
  - Calls `oauth2Client.getToken(code)` to get the `access_token` and `refresh_token`.
  - Uses the Encryption Utility to encrypt the tokens.
  - Creates a record in the `connector_credentials` table linking the user, the `google` connector, and the encrypted tokens.
  - Returns a simple HTML response: `<script>window.opener.postMessage('oauth-success', '*'); window.close();</script>` to notify the frontend.

## Testing Decisions

- Unit test the encryption utility to verify that text encrypted can be successfully decrypted and that the GCM auth tag is verified.
- Write integration tests for the endpoints by mocking the `googleapis` module.

## Out of Scope

- Token refreshing logic.
- Revoking access or disconnecting the account from the UI.
